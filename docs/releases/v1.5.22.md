## What's new in 1.5.13

**Model Race — neu.** Ein Prompt, mehrere Modelle, direkter Vergleich: ⋮ → „Race models…",
2–3 Modelle wählen, jedes läuft in **eigener Session im selben Projekt**. Die Vergleichskarte

Dazu ein Fix am neuen Controller: Antworten wurden nur über `role` gelesen, V2-Nachrichten
tragen `type` — vom neuen Mock-Server-Test aufgedeckt.

**Offline-Outbox — zweites neues Feature.** Ein Prompt, der wegen fehlender Verbindung nicht gesendet
werden konnte, geht in eine Outbox (Zeile über dem Composer mit „Send now" / „Discard all") und wird
**automatisch** zugestellt, sobald der Server erreichbar ist — in Reihenfolge, pro Session, mit
steigendem Backoff (2 s → 30 s, max. 5 Versuche) und persistent über App-Neustarts. Echte
Ablehnungen (HTTP 4xx, Guard-Konflikt) werden weiterhin sofort gemeldet und nie eingereiht.

## What's new in 1.5.19

**Absturz beim Öffnen einer Session behoben.** Die 1.5.18 stürzte beim Betreten eines Chats ab
(`NullPointerException`): der neue Glance-Feed wurde im `init` des ChatViewModel gestartet und las
dort ein `by lazy`-Feld, das zu diesem Zeitpunkt noch nicht existiert (Main.immediate führt den
Coroutine-Rumpf sofort aus). Der Feed startet jetzt nach der Konstruktion in `loadSession()`.

Der Fehler wurde über **adb** gefunden und die R8-minifizierte Spur mit dem R8-Mapping
**retraced** (`mx.s` → `ChatViewModel.getConversation` ← `ChatViewModel.<init>`); die
Crash-Historie aus `dumpsys dropbox` zeigte genau drei Einträge. **Auf dem Gerät verifiziert:**
Deep-Link in eine Session, Kaltstart und Hintergrund-/Vordergrund-Zyklus laufen ohne einen
einzigen FATAL-Eintrag.


## What's new in 1.5.20

**Entscheidungen (Journal) werden jetzt zuverlässig gespeichert.** Drei Ursachen behoben: der
stille Abbruch ohne Projekt-Verzeichnis (offline/neue Sessions — der Eintrag wurde gar nicht
gespeichert), ein Schreibpfad, der ohne Kontext lautlos ins Leere lief (jetzt `ensureContext`

## What's new in 1.5.21

## Install

1. Download the APK to your phone.
2. Allow **"Install unknown apps"** for your browser / file manager when prompted.
3. Open the APK and install.
4. Launch the app and enter your OpenCode server address, e.g.
   `http://192.168.1.100:4096` (the app starts on a backend picker; no server is
   baked in).

Updates install straight over previous versions, because every release is signed
with the same key.

## Requirements

- Android **7.0 (API 25)** or newer.
- A reachable OpenCode server exposing its HTTP API (e.g. `opencode serve`),
  on the same LAN, VPN or tunnel as the phone.

## Highlights

- **Live streaming chat** over SSE with a stable running indicator, progressive
  Markdown and syntax-highlighted code.
- **Inline tool calls** — shell, read, edit and diff rows, with consecutive
  identical calls collapsed.
- **Permission prompts & agent questions** answerable in-app or from a
  notification action.
- **Per-session model / agent / variant selection**, synced with the server.
- **Provider management** — browse the catalog, connect or disconnect
  credentials.
- **Review / Changes tab** with branch badge and on-demand working-tree diff.
- **Sessions & history** — project grouping, offline cache, older-message
  paging and history search.
- **Background continuity** — foreground session service, home-screen widget and
  a Quick Settings tile.
- **Share target** for text and images; multiple themes and custom fonts.

## Privacy

No analytics or third-party telemetry. The app talks only to the server URL you
configure. Credentials, cached conversation text and crash reports are excluded
from cloud backup and device transfer. Full details in
[SECURITY.md](https://github.com/scalyxapp-jpg/OpenCode-2.x-Android-App/blob/main/SECURITY.md).
